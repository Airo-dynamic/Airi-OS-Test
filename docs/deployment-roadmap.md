# 长期运行的 AiriOS 设备

最终设备运行 AiriOS，通过独立供电保持在线，用隔离开关接入台式机主板的电源按键接口，并提供动态 C++ 服务与原生 Cloudflare Tunnel。首选调查 x86 开发板，实际板型仍未确定。QEMU q35、单核、256 MiB、OVMF 继续作为可重复的课程基准；第二架构在有明确硬件目标后再移植。

P1–P6 的旧检查点保留。升级从 K34 追加，自己的 day2 目录仍按 03 向后连续增长；图形支线可以随时暂停。

先做可靠单核，P14 仍是正式强化阶段。第一版服务控制在 16 个并发 HTTP 请求与一个有界计算 worker；内存、队列、执行时间和进程故障分别有上限。Raft/KV/RocksDB 在网络库基础适配之后独立推进，不成为首次远程开机的前置。

这里的 HTTP/2 隧道不是向 Cloudflare 发一个普通 HTTP 请求。需要核对出站 TLS 连接上的流角色、注册与控制 RPC、配置更新、代理请求和断线重连。前置宿主原型验证协议可行性，最终运行路径由板上 AiriOS 承担。

## 自己实现与复用的边界

内核、设备访问、Ethernet/IP/TCP、等待与 I/O 生命周期、Server-Lib 及隧道会话控制属于自有实现。密码算法、TLS、C++ runtime、HTTP/2/HPACK 和 Cap’n Proto 可以采用成熟库，固定版本、来源、许可、构建参数和适配接口。Cap’n Proto RPC 还需要运行时与事件循环接入，不能以编码器可编译代替注册成功。

课程按工作性质组织：核心机制继续完整带敲并配原生旁注；依赖构建、打包和平台集成提供完整源码、固定输入与复现步骤，不要求所有机械代码逐行跟敲；第三方和生成文件提供配方及校验。集成前置必须出现在检查点依赖里，不能导入未声明的最终实现。现有章节保留原来的完整源码覆盖规则。

本地桌面、串口和未来 WebUI 都消费内核服务。WebUI 可先通过宿主串口网关观察；该网关不替代最终板上的网络、服务器或 Cloudflare 客户端。GUI 仍在独立 gui 分支，不进入默认构建。

## 选板与电源控制

购买前核对准确的网卡控制器、GPIO 控制与复用方式、UEFI/串口恢复、退出固件服务后的存储访问、RTC/看门狗和独立供电。Linux 驱动正常仅能证明该环境可用，不能代替 AiriOS 的寄存器资料与驱动验证。当前不承诺任何候选板已经满足这些条件。

按键控制使用与机箱电源按钮并联的隔离开关，接线、电平和反馈须按实际主板手册核对。服务仅提供状态、ensure_on 和操作结果，通过受限本地 IPC 驱动物理开关；不暴露任意 GPIO 操作。输出默认释放，脉冲有硬件限时；电源状态未知或指示灯含义不明时不按键，重启后不自动重放结果不确定的按键操作。还须验证台式机有市电、待机供电及电源功能正常，不能将物理按键路径称为任意故障下的绝对保证。

2026-10-23 已按用户授权创建专用 `airios-lab-20261023` Tunnel，凭据仅保存在本机私有目录；未创建 DNS 路由；官方 cloudflared 2026.7.3 使用内置 404 服务做短时 HTTP/2 对照，6.67 秒内观察到 Registered tunnel connection 后已终止。该结果确认本机网络与测试资源可完成官方注册，宿主 C++ 原型与 AiriOS 原生客户端仍未验证。真实板与主板型号也未接入。内核、Linux 实验与宿主协议开发继续按各自依赖推进。

Cloudflare 创建流程依据[官方本地管理文档](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/create-local-tunnel/)，本轮[参考客户端记录](../.codex/teaching/validation/cloudflare-reference-20261023.json)只作为后续自研实现的对照，不计为自研隧道功能。

P7当前停点已到K40：K34–K36提供持续回收与用户监督，K37扩大用户容量，K38增加有界内核堆，K39提供独立service启动与坏初始ELF恢复，K40接通当前q35块设备IRQ及PIT后备。P8已追加K41用户x87/SSE2状态，K42追加用户FS基址与隔离，K43已接静态ELF TLS与C11本地变量，K44提供errno与文件源码包装，K45已提供有界preadv/pwritev，K46补齐有符号定位，K47增加名义单调查询，K48接入单线程用户对象分配，K49再分出用户内存所有权与exec局部替换，K50归拢执行现场和等待，K51修正TLS零尾部与普通LOAD的关联，K52提供同进程共享执行者与阻塞join，后续继续futex和运行库；尚未开始真实板部署或长时间稳定性验收。

## P8 从 K56 继续的实现顺序

以下是尚未实现的下一组工作，不能用当前回归通过替代它们的验收。K41–K52已经具备用户CPU状态、静态TLS、errno、文件源码包装、显式偏移向量、有符号定位、名义单调时间、有界用户对象分配、独立用户内存所有者和执行现场。

K48已将纯堆算法另编译进用户ELF，按需申请256KiB arena，提供单线程malloc/free/calloc/realloc。真实guest验证页预算不足后的首次申请重试、16字节对齐、复用清零、乘法溢出、瞬时容量不足时保留旧对象、128轮复用及fork/exec隔离；free保留页面缓存到exit/exec。后续运行库若需要更大容量或并发，再扩展这项明确边界。

K49已将地址空间与页面记录收进user_memory，K50将CPU现场、内核栈和等待归入execution。K52进一步提供同进程共享内存、FD和异步owner的工作执行者，独立用户栈/TLS及内核栈/FPU；新执行者继承创建者浮点环境，TLS重新取ELF初值。主执行者管理创建和join，工作return只结束自己，原始exit或用户CPU故障结束整个进程组。该受控生命周期尚不提供主线程独立退出或通用共享引用计数。

当前全系统八工作槽，用户栈/TLS最多144页缓存至exec/exit，内核资源在join后安全栈上归还；反复复用已实测。工作者未收拢期间fork/exec/waitpid/release明确EBUSY，阻塞FD的close也返回忙。用户malloc仍单线程；随后要用真正futex和互斥保护共享对象，再逐步放宽兼容范围，不能把这些限制伪装成完整pthread。

futex从同一地址空间内的对齐32位值开始：比较期望值和登记等待必须连贯，唤醒按地址空间与用户地址关联，错误指针不形成内核裸引用。先展示比较失败立即返回、先唤醒后等待、多个等待者、退出清理和有限超时，再让用户互斥量用原子操作与等待组合。当前10ms名义PIT时钟只作为初始超时基础，独立clocksource与SMP同步另行强化。

共享线程路径稳定后，再接C++运行库及Server-Lib的最小单Reactor，而不是先伪造pthread、socket或fsync成功。每个真实可运行停点继续给完整带敲、画像、故障操作、独立重建和运行证据；旧00–02与学习目录保持。

K53已增加私有futex WAIT/WAKE、名义PIT超时、原始参数拒绝和进程键隔离。下一步将原子所有权与阻塞通知组合成有界互斥，再处理线程安全用户分配与POSIX线程源码接口；SMP队列同步、优先级继承及跨进程共享futex不在当前完成范围。T04另行接入精确替换作者工具，既有检查点不回写。

K54已组合有界用户互斥，验证六十四次带锁主动换执行者的普通数据更新、错误所有者和非robust死亡。下一步给分配器元数据加锁并避免realloc/calloc重入，再推进运行库；当前身份查询、释放通知仍有系统调用，快速路径优化需要同时维护fork/exec身份。

K55已同步用户分配器并保留容量、fork/exec与失败旧对象语义；四执行者共享arena和对象交接已验证。下一步优先处理快速TID查询及fork后运行库缓存更新，再减少无等待通知，继续POSIX线程与C++运行时适配。当前单锁、单arena和名义PIT预算保持，不宣称完整现代运行库。

K56以内核维护的版本化TCB直接提供TID，原始fork也正确更新，不依赖用户缓存补救。下一步先提供每执行者陷入计数形成真实基线，再以参与者登记/复查协议减少无等待通知；不争用成本与竞争、截止和清理分别验证。

K57已建立每执行者实际请求计数和八对局部锁基线，fork/worker清零、exec保留均实测。下一步加入竞争参与者登记及二次争取，只有确无参与者才省略解锁通知；保持固定截止和所有退出清理，再继续条件等待与POSIX线程/C++运行时。

K58已完成有界所有权锁的无竞争通知优化及统一撤销，保留真实竞争、PIT超时、非robust死亡与共享malloc。接下来用受控调度观察登记前、登记后和内核登记前窗口，然后实现条件等待、POSIX线程源码子集及C++运行时。

K59已验证登记前、登记后、复查后释放，以及内核等待后释放的四种实际交错；普通锁机器码保持K58。后续以序号变化、谓词与锁交接建立条件通知，再实现有界生产消费及POSIX/C++运行时；不把测试回调链接进普通程序。

K60已增加私有变化序号通知，早发布不睡错、无变化通知重查、两人广播和新快照到期实测。32位饱和明确失败，是有限生命周期原语，长期部署仍需宽代次或静止重建；下一步实现有界生产消费、关闭排空与背压，再继续POSIX/C++。

K61已增加四槽有界用户工作队列，真正阻塞生产者、空满超时、关闭唤醒两侧及排空实测；两生产者/两消费者锁外完成48项计算。后续从线程函数/结果与正错误返回开始逐步接POSIX源码接口，再扩展运行库；未宣称完整pthread或无限代次。

K62已实现pthread形状的create/join/self/equal及正确类型、正错误、包交接。34次实际worker、八槽容量、二十四复用和malloc失败均验证。当前仍主管理，下一步先放宽同进程创建与join生命周期，再接互斥/条件变量和C++；未把占位接口当完成。

K63已允许同进程worker创建其他worker，36次实际生命周期中验证creator槽/TP复用时leaf仍活着且TLS独立。下一步给join目标加唯一认领并检查循环等待，再开放对等worker收取；主执行者独立退出仍需后续。

K64已开放worker间join，加入唯一认领和有界闭环检测；同一组真实对象的争抢22、闭环35、坏输出14及后续fork均验证。主目标仍不可join，独立主退出/取消/detach保留后续；接下来推进互斥和条件源码接口。

K65已提供pthread互斥的默认ERRORCHECK、属性和生命周期，内部超时重试与64次竞争更新实测。条件等待还需跨释放/重新取得保持使用寿命；长期高频通知亦需更宽代次，接下来先增加64位私有等待与宽键隔离，再接条件接口。

K66已完成64位私有futex及process/VA/宽度键，旧32位路径保持。下一步让宽序号的输出值与错误状态分开表达，再接条件等待与生命周期；不能沿用long非负返回约定而丢掉uint64_t最高位。

K67已完成宽变化序号与错误通道分离，推进/通知各自可控。下一检查点接入pthread条件等待的释放与重取、动态互斥绑定和存活引用；当前旧队列未迁移，不据此宣称完整POSIX条件变量。
