# 围绕存储与 I/O 推进内核主线

第一轮目标是减少开发 BOSS、Taishan 时接触系统调用及以下机制的摩擦。每阶段从项目里的具体疑问进入 Linux 小实验，再在 AiriOS 实现范围受控的机制，最后回看真实代码。内核与 Linux 对照共同构成必修主线；图形工作站、WebUI 和开发板分别作为可选扩展。

## 当前课程与后续实现

main 已发布23个检查点：00–10、K11–K17、L01–L02、T01–T03。K13 提供串口日常构建、运行与验证，L01 对照 Linux 入口和系统调用，T01–T03 写出重建与快照工具。它们都可以在没有 GUI 的工程中完成，实际运行证据见[验证记录](verification.md)。

| 阶段 | 自制内核的可运行成果 | Linux 及项目对照 | 当前状态 |
| --- | --- | --- | --- |
| P1 | 独立 ELF、串口、启动合同、文本命令和真实输入 | main/_start、函数与 syscall、GDB | 已提供实现及 L01 教程；实测环境另行记录 |
| P2 | 异常报告、页分配、自己的页表与权限、内核堆 | mmap、触页、RSS、/proc、内存压力 | K14–K17内核实现与QEMU验证完成；L02完整代码已提供，SSH255，Linux运行未验证 |
| P3 | 时钟、任务切换、用户态、syscall、静态 ELF、最小 fork/exec/wait | PID、FD 继承、COW、上下文；线程与 bthread 的区别 | 待实现 |
| P4 | FD、内存文件、管道、单队列 virtio-blk、追加日志与恢复 | pread/pwritev、短读写、直接 I/O、页缓存、同步与原子替换 | 待实现 |
| P5 | 阻塞与唤醒、管道就绪、固定缓冲区提交/完成队列 | 条件变量/futex、epoll LT/ET、io_uring、背压与错误完成 | 待实现 |
| P6 | 串口沿同一请求显示运行、等待、完成与继续 | 同步 I/O、网络就绪与异步完成在相同负载下的行为 | 待实现 |

首轮按单核、固定 QEMU、静态 ELF 和每进程单线程推进。fork 先直接复制内存，COW 先在 Linux 上观察；virtio-blk 先采用有超时的单队列轮询，设备中断完成另列扩展。管道就绪与有限异步队列只实现当前操作所需行为，不承诺兼容 Linux ABI。

Linux 工具随实际观察引入：P1 使用 GDB、反汇编和 strace，P2 再观察 /proc、vmstat 与缺页，P4 进入 iostat 与同步路径，P5 观察 ss、调度等待和 perf。每项实验记录自己的参数、权限和环境，不把工具名称当作已经完成的实验。

内核首轮可将 16 周、每周 6–10 小时作为参考预算，Linux 实验按实际检查点安排。编号表示源码阶段，不对应日历天数。图形有独立的 15 个检查点，应另列数十小时预算，并按阅读和跟敲速度调整。

## 独立图形分支

[gui 分支课程](https://github.com/Airo-dynamic/Airi-OS-Test/blob/gui/dev-log/graphics/README.md)含 G11–G24、G26 共 15 个节点，从共同的 00 根提交分叉，只增加图形自己的路径。它可以合入 main 的任一现有阶段；运行图形需 K11，G24 的 guest 接入需 K13。G11–G23 先提供宿主观察，G26 验证双主题与图形状态。图形进度不成为 P2 的前置，默认主线构建始终选择串口实现。

当前图形参考提供窗口、会话内文件编辑和真实 guest 控制台显示，尚无自己的进程、持久文件系统或 Lua 执行服务。用户态窗口服务、共享表面、IPC 背压、应用退出回收、持久工作卷及系统内编程，依赖相应内核机制完成后再实施。[视觉设计](https://github.com/Airo-dynamic/Airi-OS-Test/blob/gui/docs/design.md)保存工作站目标，其初估工时不计入本轮主线交付。

## 无屏与移植扩展

WebUI 优先由宿主网关读取真实 guest 状态；设备自身的网络与 HTTP 另行实现。真实开发板尚未选型，x86-64 QEMU 继续作为学习平台。第二 CPU 架构与板级驱动有明确目标后独立移植。

AiriBoot 仍是独立的 UEFI 引导子项目：先写 UEFI 观察器，再装载静态 ELF，最后生成启动合同并退出固件服务。参考预算 30–50 小时，初期与 Limine 共存，当前尚未实现装载器。
