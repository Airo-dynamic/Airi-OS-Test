# 下一阶段：让内核报告自己的异常，再管理一页内存

当前K13依靠Limine建立的映射运行，没有自己的异常处理、页分配器和用户态。下一项实际实现从异常入口开始：执行一条非法指令时，由自己的入口保存现场，报告异常编号与指令地址，再明确停机。先解决“错误发生在哪里、能留下什么证据”，再让页表错误变得可解释。

后续检查点依次提供完整代码与观察：

1. 建立x86-64异常描述与汇编入口，用非法指令验证现场保存、调用约定和具体错误报告。
2. 依据BootInfo的可用与保留范围建立物理页状态，分配、释放并重新取得一页；暂不回收仍被启动环境借用的区域。
3. 建立并切换自己的页表，映射该页并打印虚拟地址与物理页的关系；再演示权限错误访问，报告对应的故障地址。
4. 在已有页管理之上提供内核堆，区分申请的字节、占用的页和分配器元数据。

每项都以串口报告结果和具体错误。后续 Linux 实验将观察 mmap、触页、RSS、缺页与 /proc，再用这些现象解释 BOSS 进程的内存行为；自制内核则逐项实现自己的页面和分配管理。

这些是后续待实现检查点，当前没有把未完成的IDT、分配器或堆放入构建。图形集合的任何进度都不成为它们的前置。
